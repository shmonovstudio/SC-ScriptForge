# Подготовка и загрузка на GitHub

## Что входит в репозиторий

- Исходники C#, Avalonia, PowerShell, файлы проектов и список встроенной библиотеки.
- Ровно 22 штатных скрипта и 22 файла метаданных из `Build/BundledScripts.props`.
- Ресурсы приложения: значки, логотипы, шрифты и их лицензии.
- Документация, MIT, уведомления о сторонних компонентах.
- Версии SDK и NuGet-зависимостей: `global.json`, `NuGet.Config`, `packages*.lock.json`.
- Скрипты сборки и проверок, workflow GitHub Actions.

## Что остаётся только локально

| Категория | Примеры |
| --- | --- |
| Сборки и диагностика | `bin/`, `obj/`, `dist/`, `artifacts/`, `TestResults/`, логи, дампы |
| SDK и кеш зависимостей | `.tools/`, `packages/`, `.nupkg` |
| Компоненты ИИ | `AI/Runtime/`, модели GGUF/ONNX, незавершённые загрузки |
| Рабочие данные | Всё в `Data/`, кроме явно разрешённых штатных файлов |
| Секреты и личные настройки | `.env`, ключи, настройки ИИ, профили и история |
| Настройки рабочего места | `.vs/`, `.idea/`, `.vscode/`, `.claude/`, `.codex/`, `.agents/`, `*.user` |
| Архивы и приложения | ZIP/7z, EXE/DLL, установщики, архивы предыдущих выпусков |
| Внутренние материалы | Старые планы миграции, прототипы, неиспользуемые изображения и промежуточные ресурсы |

Исключения ничего не удаляют с диска. Встроенные скрипты являются публичными исходниками: не сохраняйте в них пароли, реальные адреса вашей организации и персональные данные. Пользовательские скрипты размещайте под другими именами; файл с именем из штатного списка остаётся частью исходников.

## Проверка и архив исходников

Выполняйте команды из корня проекта в PowerShell 7:

~~~powershell
# Только при первом создании репозитория:
git init -b main

# Проверить отслеживаемые и новые файлы:
pwsh -NoProfile -File .\Tools\Prepare-GitHub.ps1

# Создать ZIP исходников, список файлов и SHA256:
pwsh -NoProfile -File .\Tools\Prepare-GitHub.ps1 -CreateArchive

# Собрать и выполнить проверки приложения:
pwsh -NoProfile -File .\Tools\Test-Windows.ps1
~~~

Архив создаётся в исключённой папке `artifacts/github/`. Он содержит текущие версии файлов на диске, включая новые файлы, и не содержит `.git`. Для работы с GitHub предпочтительнее отправлять сам Git-репозиторий; загрузка одного ZIP через браузер не создаёт исходное дерево проекта.

Проверка обнаруживает отсутствующие ресурсы библиотеки, запрещённые типы файлов, принудительно добавленные игнорируемые файлы, отдельные файлы больше 50 МиБ и типовые секреты. Секреты проверяются в рабочих файлах и добавленных строках индекса Git. Перед первым коммитом просмотрите содержимое, которое собираетесь опубликовать; после проверки добавляйте файлы в индекс заново, если меняли содержимое.

## Первый коммит и отправка

Создайте пустой репозиторий на GitHub с нужной видимостью, без автоматически создаваемых README, `.gitignore` и лицензии: эти файлы уже подготовлены здесь.

~~~powershell
pwsh -NoProfile -File .\Tools\Prepare-GitHub.ps1
git add .
git diff --cached --stat
git diff --cached --name-only

# Также отклоняет игнорируемые файлы, добавленные через git add -f:
pwsh -NoProfile -File .\Tools\Prepare-GitHub.ps1
git commit -m "Initial import of SC ScriptForge 1.6.1"

# Замените OWNER и REPOSITORY своим адресом:
git remote add origin https://github.com/OWNER/REPOSITORY.git
git push -u origin main
~~~

Перед публичной отправкой проверьте имя автора и e-mail: они входят в каждый коммит. Для приватности используйте публичный псевдоним и noreply-адрес из настроек GitHub. Настройте их только для этой копии проекта:

~~~powershell
git config --local user.name "YOUR_GITHUB_USERNAME"
git config --local user.email "YOUR_GITHUB_NOREPLY_EMAIL"
git log --all --format="%h %an <%ae> | %cn <%ce>"
~~~

Изменение этих настроек действует на новые коммиты. Перед публикацией также проверьте уже существующую историю. Для авторизации используйте ваш обычный способ входа в GitHub; токены не сохраняйте в файлах проекта или URL репозитория.

## Последующие изменения

При добавлении штатного скрипта синхронно обновите `Build/BundledScripts.props` и точные разрешения в `.gitignore`. Добавляйте метаданные `.ps1.meta.json` вместе со скриптом. Lock-файлы NuGet включаются в коммит.

`.gitattributes` задаёт окончания строк: CRLF для PowerShell и CMD, LF для остальных текстовых файлов. Шрифты и изображения хранятся как бинарные ресурсы.

После отправки GitHub Actions выполняет проверки на Windows, тесты без скачивания модели ИИ и пробную автономную публикацию. Workflow не публикует GitHub Release и не отправляет рабочие данные. Схема CI основана на [документации GitHub](https://docs.github.com/en/actions/tutorials/build-and-test-code/net), [setup-dotnet](https://github.com/actions/setup-dotnet) и [checkout](https://github.com/actions/checkout).

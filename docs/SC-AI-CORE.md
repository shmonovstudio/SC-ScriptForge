# SC AI Core · выпуск SC ScriptForge 1.3

Документ сохраняет описание исходного выпуска 1.3. Актуальная установка 1.6, докачивание, каталог 2B / 4B / 9B и режим GPU описаны в [LOCAL-AI-INSTALLATION.md](LOCAL-AI-INSTALLATION.md).

## Что реализовано

Исправления ошибок выполнения, проверка модулей/CIM и устранение ложного тайм-аута загрузки описаны в [разборе от 25.10.2026](AI-REPAIR-2026-10-25.md). Для задачи исправления одного корректного синтаксиса недостаточно: проверенные ошибки вызовов блокируют сохранение и возвращаются модели.

Отдельный переиспользуемый проект `SC.AICore` (`net10.0`, без NuGet-зависимостей) содержит контракт `IAiRuntime`, потоковые сообщения и адаптер собственного процесса llama.cpp. Он не зависит от Avalonia, ScriptForge, файлов скриптов или редактора. В приложении находятся `ScriptAiService`, MVVM-модель помощника и представления. Интерфейс приложения построен на Avalonia/C#.

Модель загружается только при первом запросе. Настраиваются контекст 1024–16384 токена, число потоков CPU и лимит ответа. Значения по умолчанию: 4096, не больше 6 потоков, ответ 1024. GPU offload отключён. Нет обязательных Ollama, браузера, облака или аккаунта. Без GGUF доступны библиотека, настройки, выбор файла и установщик; синтетической генерации нет.

| Задача | Результат |
| --- | --- |
| Свободный вопрос | Русский ответ с ограниченной историей последних реплик в RAM |
| Объяснить скрипт | Назначение, входные данные, результат и действия |
| Краткое описание | Предложение поля «Описание» |
| Подробное описание | Предложение поля «Заметки» |
| Название и теги | Предложение видимого названия и до 8 тегов |
| Ошибка PowerShell | Объяснение вставленной ошибки или сообщения из окна запуска |
| Потенциальные проблемы | Анализ переданного кода, с отделением предположений от фактов |
| Дописать функцию | Полная замена выбранного фрагмента, на просмотр |
| Исключения, журналирование, оптимизация, комментарии | Четыре отдельные задачи изменения кода |
| Изменения версий | Объяснение Diff выбранной прошлой версии и текущего файла |

Контекст ограничивается выбранным скриптом, функцией из AST или диапазоном строк. Автоматического чтения всего проекта нет. Максимальный исходник для инспекции — 1 МБ. Runtime применяет шаблон чата и считает токены родным токенизатором до генерации; при переполнении предлагает сократить фрагмент или изменить настройки, не обрезая код молча. Раздельные JSON Schema требуют нужные поля для каждой задачи. Незавершённый, оборванный или некорректный ответ не становится применимым предложением.

## Проверенная совместимость

Используется официальный CPU x64 **llama.cpp b11669**, на который указывает стабильный релиз v0.7.0; executable сообщает `0.7.0-dev (build 11669, commit 620d2225c)`. Поддержка Qwen3.5 проверена реальной загрузкой и генерацией, не только расширением файла.

- [Стабильный релиз llama.cpp v0.7.0](https://github.com/ggml-org/llama.cpp/releases/tag/v0.7.0), [CPU-артефакты b11669](https://github.com/ggml-org/llama.cpp/releases/tag/b11669).
- [Модель Qwen3.5-4B от Qwen](https://huggingface.co/Qwen/Qwen3.5-4B), [GGUF от автора квантования LM Studio](https://huggingface.co/lmstudio-community/Qwen3.5-4B-GGUF/tree/f9f88ac3e234be915e23811a6d28ea287bdb927e).
- [LLamaSharp: поддержка Qwen3.5 заявлена в v0.27.0](https://github.com/SciSharp/LLamaSharp/releases/tag/v0.27.0). LLamaSharp изучен, но для этого выпуска выбран процессный адаптер: native DLL и ABI не загружаются внутрь UI, а сбой или отмена runtime не требуют завершать приложение. Это не утверждение, что LLamaSharp несовместим.

| CPU ZIP | b11669 · 19 537 886 байт | `37b3efcf962847ca869745fd4ccf7f5e7e8dacfeff9fa3523b4ca8cdc66d632b` |
| Qwen3.5 4B Q4_K_M | LM Studio `f9f88ac3e234be915e23811a6d28ea287bdb927e` · 2 707 513 696 байт | `25082a7dd3776cc3c741c6347d3bd04523f05796607b3fbc32fa3a25dfa1418c` |
| Qwen3.5 2B Q4_K_M | LM Studio `bb84e11355a036e28f080c7793fa6d22b7c4e344` · 1 270 808 032 байта | `0bfe35afc9f05b7fac3fa04925e051ac7939a42a8a17ea11afc99701bea826cc` |

GGUF 2B добавлен в установщик как лёгкий вариант; генерация в этом окружении проверялась на 4B. Переход на произвольную другую версию llama.cpp не считается автоматически проверенной комбинацией. Ручной выбор файла проверяет GGUF-заголовок и архитектуру Qwen; окончательная совместимость определяется загрузкой runtime с понятной диагностикой отказа.

## Контроль действий и данные

У модели нет инструментов записи файлов или выполнения команд. Встроенный agent/tool mode llama.cpp, web UI, загрузки runtime во время генерации и внешние endpoints не включены. Процесс слушает только 127.0.0.1 на временном порту, запросы используют случайный ключ. HTTP-клиент генерации не использует proxy и redirect. Настройки окружения `LLAMA_*` / `GGML_*` очищаются перед запуском. Установка — отдельное явное действие с GitHub/Hugging Face и проверкой SHA256.

Путь сохранения: запрос → потоковый ответ → предложение → Parser → цветной Diff → отметка просмотра → подтверждение → повторный Parser → проверка SHA256 исходника и метаданных под блокировкой репозитория → атомарная запись и версия. Устаревшее предложение не перезаписывает параллельные изменения. Применение блокируется при работающем скрипте; во время применения нельзя начать его запуск или закрыть приложение посреди сохранения. Сохраняются кодировка с BOM и переводы строк; нераспознанный не-UTF-8 файл не изменяется. Идентичный код не создаёт лишних ревизий. Изменение названия сохраняет ID, имя файла и историю.

Синтаксис и границы функций получают через фиксированную команду PowerShell Parser с исходником в stdin. Ни тело скрипта, ни выражения default, ни модули этого скрипта не выполняются. PSScriptAnalyzer в окружении не установлен; его проверки не имитируются. Parser не доказывает корректность, безопасность или оптимальность предложенной логики — эти изменения остаются предметом просмотра пользователя.

Отмена разрывает запрос и завершает принадлежащий приложению native процесс; следующая генерация загрузит модель заново. Windows Job Object завершает runtime при закрытии/падении родителя. Это управление временем жизни, не песочница для произвольного чужого executable. Таймаут загрузки — 3 минуты, запроса — 10 минут. Native stdout/stderr дренируются и не сохраняются; журнал приложения содержит только тип события/исключения. Диалоги и код не пишутся в историю ИИ. В будущем общий runtime для нескольких продуктов подключается другой реализацией `IAiRuntime`; общий разделяемый сервис в этот выпуск не входит.

Установщик проверяет размер и SHA256 до подключения файла, показывает прогресс, поддерживает отмену и удаляет свой незавершённый временный файл. Отличающийся существующий файл не перезаписывается. GGUF находится вне пользовательской библиотеки, а лицензии MIT / Apache 2.0 встроены в модуль и сопровождают установку.

## Проверки и сборка

Реальная Qwen3.5 4B: русское объяснение, структурированные название/теги, изменённый код функции, потоковые фрагменты, Parser, отмена native процесса, выгрузка модели и полный путь UI-подтверждения до новой версии. Изображения `ai-live-proposal.png` и `ai-live-diff.png` содержат ответ реальной модели на изолированный тестовый скрипт.

На текущем i7-14700K / 32 ГБ, CPU, 6 потоков, контекст 4096: короткие проверочные ответы занимали примерно 9–13 секунд, рабочий набор native runtime после генерации — около 4,8 ГиБ. Это отдельные наблюдения, не benchmark и не измерение целевого i5-12500. 2B и меньший контекст доступны для снижения требований.

Release и Debug собираются локальным .NET 10 SDK. Команды:

```powershell
.\.tools\dotnet\dotnet.exe restore Tests/SC.ScriptForge.Checks.csproj -m:1
.\.tools\dotnet\dotnet.exe build Tests/SC.ScriptForge.Checks.csproj -c Release --no-restore -m:1 -p:UseSharedCompilation=false
.\.tools\dotnet\dotnet.exe build SC.ScriptForge.csproj -c Debug --no-restore -m:1 -p:UseSharedCompilation=false
.\.tools\dotnet\dotnet.exe Tests/bin/Release/net10.0-windows/SC.ScriptForge.Checks.dll --ai-live
.\.tools\dotnet\dotnet.exe Tests/bin/Release/net10.0-windows/SC.ScriptForge.Checks.dll --regression
.\.tools\dotnet\dotnet.exe Tests/bin/Release/net10.0-windows/SC.ScriptForge.Checks.dll --native-ui
```

Отчёты: `artifacts/ai-validation/results.txt`, `artifacts/ai-regression/results.txt`, `artifacts/library-validation/native/results.txt`. Проверки используют отдельные библиотеки; пользовательская Data ими не заменяется. Основной запуск — `RUN.cmd` → **SC AI**. Для исходников без runtime используйте встроенный установщик; модель в исходники и ZIP приложения не включается.

Итог: **35 PASS** для ИИ с реальной моделью, **86 PASS** полного регрессионного прогона, **9 PASS** нативной шапки, **4 PASS** установщика и **3 PASS** опубликованного runtime — всего 137, без FAIL. Установщик фактически скачал и проверил закреплённый CPU ZIP, повторно использовал модель без её перезаписи, проверил ресурсы лицензий и отмену без остаточного файла. Его отчёт — `artifacts/ai-install-validation/results.txt`. Опубликованный runtime отдельно выполнил настоящую генерацию Qwen3.5 и выгрузился: `artifacts/ai-publish-validation/results.txt`. Debug/Release: 0 предупреждений, 0 ошибок. В регрессионном прогоне также исправлен сброс вкладки просмотра при автообновлении библиотеки.

При single-file публикации native компоненты помечены `ExcludeFromSingleFile`: основной EXE содержит .NET и managed приложение, а `llama-server.exe` и DLL остаются в `AI/Runtime`, где их запускает адаптер. Скопировать только основной EXE на другой ПК недостаточно для работы ИИ — переносится вся папка выпуска и выбранный GGUF. Основное приложение при отсутствии компонентов ИИ сохраняет работоспособность.

Готовый выпуск: `dist/SC.ScriptForge.exe` версии 1.3.0.0 и `artifacts/SC.ScriptForge-1.3.0-win-x64.zip` (62,9 МиБ). Нативное окно автономного EXE отзывчиво, ИИ при старте не запускается, штатное закрытие — exit 0 (`artifacts/ai-native-startup.json`). Все 21 существующий файл пользовательских Data сохранены по SHA256 (`artifacts/ai-upgrade-result.json`). Предыдущий EXE сохранён в `artifacts/SC.ScriptForge-1.2-before-ai.exe`. ZIP проверен по хешам всех файлов относительно dist, не включает Data и GGUF; подтверждение — `artifacts/ai-release-verification.json`.

Выпуск 1.4 меняет интерфейс диалога и просмотра предложений. Схема взаимодействия, адаптация, движение и новые проверки описаны в [AI-INTERFACE.md](AI-INTERFACE.md). Результаты выпуска 1.3 выше сохранены как исходная проверка ядра.

# Архитектура SC ScriptForge 1.0

## Состав

- **SC.ScriptForge.csproj / Desktop** — единственный продукт и точка входа, WinExe net10.0-windows. Avalonia App.axaml задаёт тему, Desktop/Ui.cs — переиспользуемые элементы, MainWindow — оболочку и платформенные диалоги. LibraryViewModel и ScriptRunViewModel сохранены с переносом DispatcherTimer на Avalonia. CommunityToolkit.Mvvm реализует ObservableObject и команды обновления/отмены. Bootstrap регистрирует зависимости через Microsoft DI.
- **SC.ScriptForge.Core** — общие модели, контракты inventory/permissions/errors, структурированный журнал, существующее файловое хранилище, поиск, watcher, профили, история, diff, backup и undo. Старые сервисы подключены ссылками на исходные файлы, без копирования реализации и изменения JSON.
- **SC.ScriptForge.Windows** — Win32 token elevation, WMI, .NET-сеть/диски, DXGI, isolated category workers. Вход worker строго ограничен семью именами категорий. У worker нет UAC, shell-команд, внешних путей/кода или постоянно работающего режима.
- **SC.ScriptForge.Scripting** — отдельный процесс PS5.1/7, встроенные фиксированные wrapper/AST/report-сценарии, типизированные аргументы, SHA256-проверка актуальности формы, ACL временного payload, bounded output, таймаут/отмена, Windows Job Object. Работа с PowerShell не используется inventory.
- **SC.AICore** — контракты локального ИИ, установка моделей, адаптер llama.cpp и подключение OpenAI-совместимого сервера.
- **Tests** — исполняемый набор регрессионных и интеграционных проверок плюс Avalonia.Headless с реальным Skia-рендерингом.

## Данные и обновления

ScriptRepository сохраняет прежний portable/fallback-путь. Форматы и стабильные GUID не меняются. Новая настройка Theme добавлена с default Dark; отсутствующие свойства старого preferences.json не сбрасывают остальные. Atomic writes, snapshots до восстановления, защита путей корзины и ограниченные истории сохранены.

Обновлять следует EXE и поставляемые ресурсы, оставляя Data на месте. Build/publish не очищает каталог. Существующая dist/Data сверяется по SHA256 перед заменой основного EXE. Приложение не переносит и не сливает библиотеки между разными папками автоматически.

## Inventory и достоверность

ComputerInventory ограничивает refresh одним запросом и запускает не больше двух категорий параллельно. Каждая категория имеет собственный IInventoryCategoryService. Изолированный процесс нужен из-за отсутствия гарантированной отмены синхронных COM/WMI-провайдеров: timeout завершает его process tree, а остальные результаты сохраняются. Один query возвращает самостоятельную запись ошибки и не отменяет другие запросы категории. UI обновляется после получения snapshot; предыдущий snapshot сохраняется при отмене.

InventoryField — типизированное объединение Text/Number/Flag/Timestamp с Unit, Status, CapturedAt, Source, Error и признаком Sensitive. Отображение не хранится вместо исходного значения. Unavailable отличается от AccessDenied, Unsupported и Error; причины timeout/cancel/source/API различаются отдельно. Нули не используются как замена отсутствующих данных.

MSFT_PhysicalDisk даёт SSD/HDD и состояние только при ответе провайдера; Win32_DiskDrive служит fallback без угадывания типа. DXGI возвращает pointer-sized DedicatedVideoMemory; WMI AdapterRAM исключён. DXGI и драйвер WMI показываются отдельно, без ненадёжного сопоставления GPU по порядку. Частота CPU помечена как значение WMI, а не непрерывная телеметрия. Нагрузка CPU — разница GetSystemTimes за 400 мс. Объём памяти в UI выражен в бинарных единицах. BIOS/сеть/модули показывают только данные источника.

Серийные номера и MAC не запрашиваются. Экспорт фильтрует приватные поля, пока пользователь явно не включит их. Публичная модель не содержит произвольных команд для worker.

## Разрешения

| Действие | Требование |
| --- | --- |
| Inventory, доступное чтение, экспорт | Текущий токен; Windows/WMI проверяет доступ каждого источника |
| Файлы библиотеки, версии, backup | Права на выбранный каталог |
| Пользовательский PowerShell | Текущий токен + действующая Execution Policy |
| Bypass / RemoteSigned CurrentUser | Явное подтверждение; без UAC; групповые политики не обходятся |
| AD/WinRM/корпоративные модули | Отдельная авторизация на целевом ресурсе из скрипта |
| Привилегированная операция helper | Сейчас отсутствует; незарегистрированные действия запрещены |

Permission Manager читает TOKEN_ELEVATION, не делает вывод по членству в Administrators и не предлагает автоматический UAC после AccessDenied. CheckAsync означает допуск зарегистрированного типа операции; фактические права на данные определяются самим целевым API, а не оптимистическим предсказанием.

PrivilegedOperationBroker — контракт будущего конечного allowlist. Helper.exe будет добавлен вместе с конкретным административным сценарием, независимой проверкой параметров, объяснением последствий до runas, аутентифицированным IPC при его необходимости, обработкой отмены UAC и отдельной подписью. Никакого фиктивного helper, SYSTEM-службы или произвольного elevated runner сейчас нет.

## Ошибки, производительность, ограничения

Журнал JSONL ограничен 2 МБ с одной предыдущей копией. Он не сохраняет сообщения исключений, пути, значения параметров или текст скриптов. UI показывает короткую причину; сырой вывод PowerShell доступен только в диагностике запуска. Сам сценарий может вывести чувствительные данные: это не защищённое хранилище секретов.

Старт UI не ждёт WMI; скрипты и inventory загружаются async. Файловый поиск debounce/cancellation/cache и watcher сохранены. Фонового polling нет. После refresh worker завершается. UI-вывод ограничен очередью, предпросмотром, размером строки и журнала; отчёт сохраняет доступные таблицы. Reduced motion отключает переходы кнопок, оставляя осмысленную индикацию загрузки.

Ограничения: PS7 обнаруживается только в стандартной установке; SecureString/PSCredential требуют отдельного интерактивного сценария авторизации. Работа с AD выполняется через явно запускаемые PowerShell-скрипты. CPU/память — snapshot, не мониторинг в реальном времени. Windows 10, ARM64, несколько физических GPU и реальный multi-monitor DPI требуют отдельных проверок. Цифровая подпись/installer/auto-update не реализованы; version/product/icon и автономная CLI-публикация готовы.

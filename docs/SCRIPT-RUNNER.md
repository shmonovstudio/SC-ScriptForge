# Настройка и выполнение скриптов

В карточке сценария нажмите **Настроить запуск** или **Ctrl+Enter**. Открывается отдельное окно: слева входные параметры, справа понятный результат задачи. Само открытие ничего не выполняет. Данные сохраняются между запусками, если включено «Запомнить параметры».

Объекты PowerShell с одинаковыми наборами полей объединяются, разные — разделяются. Результат до четырёх полей показывается компактной таблицей, если хватает ширины. При пяти и более полях или в узком окне используются вертикальные карточки: подпись поля над полным значением, длинный текст переносится. Несколько записей оформляются отдельными раскрывающимися блоками; первая запись открыта сразу. Сообщения и предупреждения показаны отдельными блоками, готовые файлы — карточками. **Копировать отчёт** создаёт текстовый отчёт с таблицами для вставки в документ. Статус учитывает код завершения, ошибки и остановку; предупреждения видны даже при успешном завершении. Для неизвестной ошибки приложение предлагает проверить данные и открыть диагностику, не придумывая причину.

Чтобы получить таблицу, возвращайте обычные объекты, например результат `Select-Object`. Явный `Format-Table` уже превращает данные в оформление и поэтому сохраняется текстовым сообщением. Для карточки файла верните `FileInfo` или строку `Сохранено: <путь>`; карточка появляется только при существовании файла. Файл показывается в Проводнике, автоматически не запускается. Предпросмотр больших результатов сокращается с видимым пояснением.

**Расширенная диагностика** изначально свёрнута. Внутри доступны исходный журнал, копирование, сохранение и переход к коду. Запуск выполняется локально; для представления результатов интернет и ИИ не используются.

В окне запуска параметры и результаты разделены на две колонки с одинаковыми отступами. Готовые настройки показываются краткими значениями — например, текущий компьютер и язык отчёта. Нажмите **Изменить**, чтобы открыть поле ввода, и **Сбросить**, чтобы снова использовать значение из скрипта. Тип поля доступен в дополнительных настройках ввода. Кнопки запуска находятся в нижней панели, а копирование отчёта — над результатами.

Если подготовка или запуск не удались, окно показывает карточку **Ошибка запуска** с конкретной причиной. Для синтаксической ошибки указаны строка, столбец и фрагмент кода. Текст можно выделить или скопировать кнопкой **Копировать ошибку**. После исправления нажмите **Обновить параметры** в карточке: успешная проверка уберёт ошибку и снова разрешит запуск. Ошибки чтения файла, изменения скрипта после проверки и выполнения также сохраняют исходное описание причины.

## Если PowerShell требует цифровую подпись

В версии 0.8.1 ошибка политики выполнения показывает отдельную карточку над журналом:

1. **Только этот раз · Bypass** запускает выбранный скрипт в новом процессе с `-ExecutionPolicy Bypass`. Настройки учётной записи сохраняются прежними. Режим действует только на этот запуск и отмечается в истории; обычная кнопка и Ctrl+Enter при следующем запуске используют действующую политику.
2. **Разрешить локальные…** после подтверждения устанавливает `RemoteSigned` в области `CurrentUser` выбранного PowerShell. Это изменение распространяется на учётную запись и другие окна этой версии PowerShell. Затем выполнение запускается отдельным нажатием обычной кнопки.

Эти действия также есть в **Настройки запуска → Разрешение скриптов**. Для скачанных файлов RemoteSigned может требовать подпись. При политике организации MachinePolicy/UserPolicy кнопки недоступны с пояснением; Bypass процесса не имеет приоритета над групповой политикой. См. [области политик PowerShell](https://learn.microsoft.com/powershell/module/microsoft.powershell.core/about/about_execution_policies?view=powershell-5.1).

## Подготовка собственного скрипта

Объявите редактируемые значения в top-level `param(...)`. Для пояснений используйте стандартные комментарии `.PARAMETER`:

```powershell
<#
.PARAMETER InputFile
Исходный CSV с данными.
.PARAMETER OutputFolder
Папка готовых отчётов.
#>
[CmdletBinding()]
param(
    [Parameter(Mandatory)][string]$InputFile,
    [Parameter(Mandatory)][string]$OutputFolder,
    [ValidateSet('CSV', 'JSON')][string]$Format = 'CSV',
    [int]$MaxRows = 1000,
    [switch]$IncludeDisabled
)

# Здесь ваш код обработки, использующий эти параметры.
```

Имена вроде InputFile/ExcelPath и OutputFolder/OutputFile помогают автоматически выбрать редактор. У строкового параметра можно вручную выбрать роль: текст, входной файл/папка или файл/папка результата. Роль определяет проверку пути и диалог выбора, сам сценарий всё равно должен использовать этот параметр для записи результата.

| Объявление | Поле в форме |
| --- | --- |
| `[string]` | Текст или выбор пути |
| `[int]`, `[double]` и основные числовые типы | Числовой ввод с проверкой типа |
| `[switch]`, `[bool]` | Переключатель |
| `[ValidateSet(...)]` | Список допустимых значений |
| `[string[]]` | Несколько значений, каждое с новой строки |
| `[Parameter(Mandatory)]` | Обязательное поле |
| `ParameterSetName`, `DefaultParameterSetName` | Выбор набора и соответствующих полей |
| Имена с password/secret/token/credential | Скрытый ввод, без сохранения в профиле |

«Значение из скрипта» означает, что аргумент не передаётся. Снимите флажок, чтобы переопределить его. Выражения по умолчанию не вычисляются при построении формы. Скрипты без `param(...)` тоже можно запустить, но их внутренние переменные редактируются через редактор кода.

## Excel и CSV

В **Новый скрипт → Отчёт из Excel / CSV** встроен готовый редактируемый пример. Он принимает входной файл, папку результата, лист Excel, формат CSV/JSON, разделитель, отбор непустых строк и предел количества строк. Папка создаётся при запуске, имя отчёта включает время.

Поддерживаются `.xlsx` и UTF-8 `.csv`, первый ряд используется как заголовки. Для `.xlsx` читаются shared/inline strings и сохранённые значения ячеек; формулы не пересчитываются, оформление и форматирование дат Excel не воспроизводятся. Старый бинарный `.xls`, зашифрованные книги и `.xlsm` этот пример не обрабатывает. Excel и сторонние PowerShell-модули не нужны. Максимум — 100 000 строк, отдельная XML-часть книги ограничена 64 МБ.

Исходник примера: `Runtime/ExcelCsvReport.ps1`. Пользователь может изменить его после создания в библиотеке.

## Журнал, остановка и движок

Форма показывает Windows PowerShell 5.1 и стандартно установленный PowerShell 7, если он найден в Program Files. Процесс работает с правами текущего пользователя, в папке сценария и без интерактивного stdin. `Read-Host`, графическая авторизация, SecureString/PSCredential, динамические параметры, параметры вложенных функций и сложные объектные массивы не обслуживаются этой формой. Такие сценарии нужно подготовить к неинтерактивному выполнению или запускать отдельно.

«Остановить» завершает процесс и его дочерние процессы. Уже сделанные сценарием изменения не откатываются. Итоговый статус учитывает ошибки PowerShell и код завершения; сообщения и продолжительность остаются в журнале.

`Data/RunProfiles/<ID>.json` хранит последний профиль, `Data/Runs/<дата-ID>/output.log` — журнал. Секретные поля не сохраняются в профиле, временный JSON с аргументами удаляется после запуска. Имена полей распознаются эвристически; чувствительные данные в произвольно названных параметрах или выводе сценария автоматически не скрываются.

Перед запуском проверяется, что исходный файл не изменился после чтения формы. Это защита от случайно устаревших параметров, а не изоляция исполняемого кода: запускать следует сценарии, которым вы доверяете.
